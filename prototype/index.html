这只猫完全由代码绘制：32 个身体锚点、8 节尾巴、两节前爪。页面预览和离线导出用的是同一个渲染函数，这里看到什么，导出的视频就是什么。

结论

能做到丝滑，关键是放弃"直接出 SVG"

你之前把 Canva 图直接转 SVG，得到的是描摹出来的一整块路径：几百个节点，眼睛、胡须和身体粘在一起，节点数和顺序每张图都不一样。这种路径既不像原图，也没法做动画，因为两张图之间没有点对点的对应关系，变形必然扭曲、跳动。

换个做法：照着原图手工重建一套"骨骼"。身体是 32 个锚点，眼睛是圆，尾巴是一条有粗细的脊线。所有动作只是改这几十个数字，图形结构永远不变，所以任意两个动作之间都能平滑过渡。上面的原型就是这样做出来的。

32

个锚点画出整个身体

每个点带"头部权重"：歪头时头顶跟着转，脖子转一半，屁股不动，过渡自然没有折痕。

40

个参数驱动所有动作

眼睛开合、瞳孔方向、耳朵角度、尾巴卷曲、张嘴、炸毛……动作就是这些参数随时间的曲线。

t

帧是时间的纯函数

沿用 bloub 最核心的设计：frameAt(t) 不依赖任何状态。实时预览和逐帧导出得到完全一样的画面。

IP 设计

墨墨，一只好奇心比胆子大的小黑猫

角色名暂定「墨墨 Momo」，系列名「知识猫 GeekCat」，两个都可以换。设定：什么都想弄明白，胆子只有一点点。它在视频里负责提问、吃惊、恍然大悟，替观众说出那句"咦？"。Canva 稿里的其他姿势正好对得上这套性格：被蜘蛛吓到、炸成毛球、认真写字、从文件柜里探头、在卷轴上睡着。

设计规则

要
  • 保持纯剪影，靠轮廓和白色五官说话
  • 眼睛永远是白色，形状永远由圆裁切出来
  • 动作夸张一点：预备、回弹、尾巴跟随
  • 配饰和道具只用灵感黄、腮红粉，配墨黑描边；小鱼和蜘蛛是墨黑剪影加白色描边
  • 配饰同时最多两件，剪影要一眼认得出
不要
  • 给身体加描边、渐变、阴影
  • 给瞳孔加高光（会失去呆感）
  • 画牙齿，或者让嘴超过鼻子宽度的两倍
  • 改变尾巴粗细，或者让尾巴尖变细
动作库

17 个动作，覆盖讲解视频的常见镜头

每个动作都从待机姿态出发、能回到待机姿态，所以剪辑时任意两段拼在一起都不会跳。循环动作按整数周期导出，可以无限平铺。

配饰与场景

给剪辑用的陪伴角色工具箱

场景是"道具 + 姿态"的组合，比如举牌时爪子会自动扶住牌子，指示时会伸出教鞭。场景和配饰都能叠加，也能和任意动作组合：talk + 举牌，就是举着牌子说话。它们都是参数，切换时一样平滑淡入淡出。

场景

大姿势（参考 Canva 稿）

这 6 个姿势对应 Canva 稿里的其他形象。趴卷轴和写字用的是同一组身体锚点的另一套坐标，所以从坐姿过渡过去是连续变形，不是切图；其余 4 个复用坐姿骨骼，加上第二只前爪、整体翻转、遮挡和道具。大姿势一次只能用一个，可以和动作、配饰、文字场景组合，比如 sleep + 趴卷轴就是睡着。

配饰

配饰画在猫自己的坐标系里，外面套一个跟随矩阵，所以歪头、挤压、打滚、趴下时都贴在原来的位置。它们也有自己的反应：吓一跳时帽子和眼镜被顶起来，炸毛时眼镜被弹歪，睡着时眼镜滑到鼻梁上，跳跃下落时帽子微微飘起，铃铛和流苏有惯性，叼着的小鱼说话时会甩尾巴。

技术方案

从 bloub 拿什么，改什么

bloub 用一个黑色圆形加两只白眼复刻了 Grok 头像，工程质量很高：引擎没有时钟、动作只截断不缩放、导出是同一套渲染。这些原样继承。要改的是造型表示方法，因为猫的轮廓比圆复杂得多。

模块bloub 的做法知识猫的做法
引擎engine.sample(t) 纯函数保留。frameAt(schedule, t)，回放、导出、测试三者一致
造型64 个角度的径向半径 r(θ)，变形 = 插值半径改为锚点骨骼。尾巴会回卷、耳尖是尖角，r(θ) 表达不了；32 个锚点 + 头部权重 + 弦长切线贝塞尔
眼睛mask 镂空改为 clipPath 裁切的白色实体。镂空的眼睛导出透明视频时会透出底下的画面
过渡easeOutQuint，刻意不用弹簧切换用 smootherstep（速度连续）；动作内部允许预备、回弹、跟随。头像要克制，角色要有弹性
时间轴cycles.ts：拉长靠保持，缩短靠截断，从不缩放时间原样保留。动作时长恒定，卡点可预测
眨眼预生成的眨眼日程保留思路
视线Look：mix / wander 分离保留，增加头部跟着转一点
导出浏览器内 SVG / PNG / GIF / MP4（mediabunny）保留，另加离线渲染管线出 ProRes 4444 透明视频
新增无尾巴正向运动学 + 时间延迟跟随、两节前爪、胡须、嘴型、特效层、炸毛噪声、速度驱动的惯性

丝滑的六个来源

  1. 只插值参数，不插值路径。图形拓扑永远不变，这是能任意切换的前提。
  2. 按时间取样，不按帧推进。60Hz 和 120Hz 屏幕都按真实时间取帧；导出时按 1/60 秒精确取样，不会掉帧。
  3. 切换从屏幕上的合成帧出发。上一次过渡还没结束就点下一个动作，也是从当前看到的画面开始混合（bloub 修过的同一个问题）。
  4. smootherstep 混合。6t⁵−15t⁴+10t³ 的起止速度和加速度都为 0，过渡没有"顿一下"的感觉。
  5. 跟随与重叠。尾巴第 i 节读取 i×45ms 之前的姿态，动作像波一样从根部传到尾尖；尾巴和耳朵还读取身体速度产生惯性。两者都是纯函数，不需要物理模拟，可以回放、可以逐帧导出。
  6. 持续的小生命感。呼吸、眨眼、视线漂移、胡须轻抖、耳朵偶尔抖一下。静止的角色看起来像死机。

导出视频时还可以加运动模糊：每帧在快门时间内取 8 个子帧平均，跳跃和甩尾会更像动画片。

造型校准：让它和 Canva 原图一模一样

  1. 拿到 Canva 原始高清 PNG 或原始 SVG（现在的锚点是从 1422px 截图测的，精度有限）。
  2. 在编辑器里打开「叠加参考图」，逐个拖动锚点，直到轮廓重合。
  3. 眼睛、瞳孔、鼻子用圆拟合测量，记下圆心和半径。
  4. 冻结数值并写测试锁住。和 bloub 的规则一样：这些数字是测量值，不是可以随手取整的设置。

离线渲染管线（已实现）

render/render.mjs 按 1/60 秒步进调用 frameAt，用和网页同一个 frameSVG 生成 SVG，再用 resvg 光栅化成带透明通道的 PNG，通过管道交给 ffmpeg 编码。同一份剧本每次渲染逐像素一致。实测在 M 系列 Mac 上，1080p 60fps 的 23 秒样片渲染约 63 秒。

三种用法

  1. 动作素材包。每个动作单独导出一段，命名如 geekcat_talk_loop_3.0s_60fps.mov，在剪辑软件里像贴纸一样拖用。
  2. 剧本驱动。写一份时间表 [{"at":0,"do":"enter"},{"at":1.2,"do":"talk"},{"at":4.5,"do":"think"}]，一次渲染整段，和配音时间轴对齐。
  3. 直播 / 录屏演示。透明背景网页直接当 OBS 浏览器源；页面暴露了 window.GeekCatPlayer.play("talk")，脚本或自动化工具都能触发动作。

口型同步

已实现：剧本里写 "lipsync": "voice.wav"，渲染时用 ffmpeg 解码音频，按帧计算音量包络，映射到 mouth 参数，再整体提前 40ms（嘴先动、声音后到更像真人）。要更精细时，可以接 Rhubarb Lip Sync 把音素分成 5 种嘴型。

Agent 接入

agent 写剧本，命令行出片

接入口是一个命令行和一份 JSON 剧本，没有界面，任何能跑 shell 的 agent（Claude Code、Codex、自建流水线）都能直接用。仓库已开源在 github.com/gnipbao/geekcat-bot，附带 Codex / Claude Code / Gemini CLI 都能读的 AGENTS.md。在仓库里对 agent 说"给这个视频加上墨墨，在右下角吐槽"，它就会按流程走。

命令

git clone https://github.com/gnipbao/geekcat-bot.git && cd geekcat-bot
npm install                                                         # Node 18+，自带 ffmpeg 和中文字体
node render/render.mjs list                                         # 动作 / 场景 / 配饰目录，JSON
node render/render.mjs draft subs.srt -o work/script.json --video main.mp4   # 按字幕生成剧本草稿
node render/render.mjs validate work/script.json                    # 校验，错误信息会列出可用值
node render/render.mjs still work/script.json --at 1.5,4 -o work/shots       # 关键帧 PNG，agent 自己看一眼
node render/render.mjs render work/script.json -o work/overlay.mov  # 透明叠加层（多核并行）
node render/render.mjs composite --video main.mp4 --overlay work/overlay.mov -o final.mp4   # 合成成片
node render/render.mjs auto --video main.mp4 --srt subs.srt --corner -o final.mp4           # 一条命令出成片

仓库根目录的 AGENTS.md 是给 agent 的完整手册（Codex 直接读它，CLAUDE.md、GEMINI.md 都引用它），render/script.schema.json 是剧本的 JSON Schema。

剧本格式

{
  "width": 1920, "height": 1080, "fps": 60,
  "background": "transparent",              // transparent | green | dots | #RRGGBB
  "cat": { "x": 0.85, "y": 1.0, "scale": 0.55, "flip": false },   // 落地点在画面中的比例位置
  "accessories": ["glasses"],               // 全局默认配饰
  "lipsync": "voice.wav",                   // 可选：按音量自动对口型
  "timeline": [
    { "at": 0,   "do": "enter" },
    { "at": 1.0, "do": "talk", "scene": ["peek", "bubble"], "text": "这里有坑！" },
    { "at": 4.2, "do": "surprised" },                       // scene / accessories / text 不写就沿用
    { "at": 6.0, "do": "idle", "scene": "sign", "text": "第 2 步", "accessories": ["glasses", "cap"] },
    { "at": 9.0, "do": "exit" }
  ],
  "duration": 9.6
}
字段说明
at秒。动作从这一刻开始，和上一个动作平滑混合
do动作 id，见上方动作库。不写则保持当前动作，只换场景或配饰
scene字符串或数组，null 清空。粘性：后面的条目不写就沿用
accessories数组，[] 清空。粘性
text牌子或气泡上的字，\n 换行。也可以写成 {"sign": "…", "bubble": "…"}
cat.x / cat.y猫的落地点在画面里的位置，0–1。角落探头时 y 设为 1.0
cat.flip镜像。猫默认朝左看，放在画面左侧时设为 true，让它看向画面中间

agent 的标准流程

  1. 读口播稿或字幕的时间戳。从剪辑工具导出 SRT，或读转写结果，找出每句话的开始时间。
  2. 写剧本。说话段落用 talk，提问用 curious，结论用 think 的灯泡，强调句举牌写关键词。动作切换放在句首前 0.2 秒。
  3. validate 校验，still 抽 3–5 帧看构图。重点看猫有没有挡住主体、字有没有超出牌子。
  4. render 出 .mov。透明通道直接叠在主视频上方。
  5. 放进剪辑工具。Premiere / Final Cut / 达芬奇：拖到主视频上方轨道。剪映手机版：渲染 .mp4（自动绿幕），用色度抠图。ChatCut：让 agent 把 .mov 导入为素材，放到主轨之上的叠加轨，起点对齐时间轴 0 秒。

开工前需要你拍板的事

  1. 素材授权。这组猫看起来像 Canva 素材库里的插画。Canva 的授权一般不允许把素材元素用作商标或 IP 形象。如果要当长期品牌用，最好确认原作者授权，或者以它为参考重新设计。重绘版只要比例、五官有明显区别，风险会小很多。
  2. 视角限制。现在所有姿势都是同一个 3/4 侧面视角。趴、弓身可以和坐姿连续变形；行走、转身、正面需要新视角的锚点，属于下一阶段。
  3. 名字和性格。「墨墨」和"好奇但胆小"的设定是提案，确认后再写进规范。
  4. 原图精度。我没有你的 Canva 登录权限，公开网页上也搜不到这组素材。请在 Canva 里选中猫，点「分享 → 下载」，选 PNG、尺寸 ×3 或 SVG（需 Pro），把文件放进项目目录，我再精确对齐一遍。
